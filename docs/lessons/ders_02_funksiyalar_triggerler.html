2.1. Köməkçi funksiyalar (2)

1

ref.set_updated_at() — trigger funksiyası

updated_at sütununu avtomatik yeniləyir. Bu, hər BEFORE UPDATE triggerinin ürəyidir. NEW — dəyişdiriləcək yeni sətir deməkdir.

CREATE OR REPLACE FUNCTION ref.set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at := NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
2

ref.normalize_text(t TEXT) — mətn normallaşdırma

Axtarış üçün mətni kiçildir və Azərbaycan hərflərini Latın ekvivalentinə çevirir: Ə→A, Ö→O, Ü→U, Ç→C, Ş→S, I→I. IMMUTABLE — eyni girişə həmişə eyni çıxış (indeks üçün əlverişli).

CREATE OR REPLACE FUNCTION ref.normalize_text(t TEXT)
RETURNS TEXT AS $$
BEGIN
    RETURN lower(translate(t, 'ƏəÖöÜüÇçŞşIİ', 'AaOoUuCcSsIi'));
END;
$$ LANGUAGE plpgsql IMMUTABLE;

2.2. Biznes funksiyaları (9)

3

layihe.layihe_progres(p_layihe_id) — layihə progressi

Layihənin mərhələlər üzrə orta real faizini qaytarır. COALESCE(AVG(...), 0) — mərhələ yoxdursa 0.

SELECT COALESCE(AVG(real_faiz), 0)
INTO v_progres
FROM layihe.layihe_merhele
WHERE layihe_id = p_layihe_id;

maliyye.layihe_umumi_xerc(p_layihe_id) — ümumi xərc

Layihə üzrə bütün xərclərin cəmi. Bu funksiya başqa funksiyalar tərəfindən də çağırılır (komponent yanaşması).

SELECT COALESCE(SUM(mebleg), 0)
INTO v_toplam
FROM maliyye.xerc
WHERE layihe_id = p_layihe_id;
RETURN v_toplam;
5

maliyye.layihe_budce_istifade(p_layihe_id) — büdcə istifadə faizi

Plan büdcənin nə qədəri xərclənib. 4 nömrəli funksiyanı çağırır. Plan 0-dırsa 0 qaytarır; nəticəni 999.99 ilə məhdudlaşdırır.

v_xerc := maliyye.layihe_umumi_xerc(p_layihe_id);
IF v_plan IS NULL OR v_plan = 0 THEN RETURN 0; END IF;
v_faiz := ROUND(100.0 * v_xerc / v_plan, 2);
RETURN LEAST(v_faiz, 999.99);
6

maliyye.muqavile_borcu(p_muqavile_id) — qalıq borc

Müqavilə məbləği ilə edilən ödənişlər arasındakı fərq.

SELECT m.mebleg - COALESCE(SUM(o.mebleg), 0)
INTO v_borc
FROM satinalma.muqavile m
LEFT JOIN maliyye.odenis o ON o.muqavile_id = m.muqavile_id
WHERE m.muqavile_id = p_muqavile_id
GROUP BY m.muqavile_id;
RETURN COALESCE(v_borc, 0);

satinalma.tender_qenayeti(p_tender_id) — tender qənaəti

Elan qiymət həddi ilə qalib təklif arasındakı fərq = dövlət vəsaiti qənaəti.

SELECT t.qiymet_serhedi - ti.teklif_mebleg
INTO v_qenayet
FROM satinalma.tender t
JOIN satinalma.tender_istirakci ti
  ON ti.tender_id = t.tender_id AND ti.qalib = TRUE
WHERE t.tender_id = p_tender_id;

risk.risk_derecesi(p_ehtimal, p_tesir) — risk dərəcəsi

Standart risk düsturu: ehtimal × təsir / 100. Nəticə 0–100 arası. Bu funksiya risk.risk cədvəlindəki GENERATED sütunun riyaziyyatını təkrarlayır.

RETURN ROUND(p_ehtimal * p_tesir / 100, 2);

kadr.layihe_kadr_deyeri(p_layihe_id) — kadr dəyəri

Layihə üzrə işçilərin ümumi dəyəri: günlük məbləğ × iş günləri. Tarix yoxdursa cari tarix qəbul edilir.

SELECT COALESCE(SUM(
    gunelik_mebleg * COALESCE(
        (COALESCE(son_tarix, CURRENT_DATE) - COALESCE(bashlama_tarixi, CURRENT_DATE)),
        0)

INTO v_deyer
FROM kadr.layihe_isci_teyinat

ai.ai_plan_budce_prognozu(p_layihe_id) — AI büdcə proqnozu

Bu layihənin fərqləndirici funksiyasıdır. Sadə riyazi model: cari xərc / progress → tamamlanma proqnozu. Progress 0-dırsa plan qaytarır (hələ başlamayıb).

v_xerc := maliyye.layihe_umumi_xerc(p_layihe_id);
v_progres := layihe.layihe_progres(p_layihe_id);
IF v_progres <= 0 THEN
    v_prognoz := v_plan;
ELSE
    v_prognoz := ROUND(v_xerc * 100.0 / v_progres, 2);
END IF;
RETURN v_prognoz;

Məntiq: əgər layihə 60% icra olunub və 68,700 AZN xərclənibsə, tamamlanma proqnozu = 68,700 × 100 / 60 ≈ 114,500 AZN.

audit.audit_trigger_func() — ümumi audit funksiyası

Ən mürəkkəb funksiya. İstənilən cədvəldə INSERT/UPDATE/DELETE-i izləyir:

  • OLD/NEW sətirlərini JSONB-yə çevirir;
  • Sətirin əsas açarını avtomatik tapır (%_id ilə bitən sütun, lakin parent_id istisna);
  • audit.audit_log-a qeyd yazır.
IF TG_OP IN ('UPDATE','DELETE') THEN old_json := to_jsonb(OLD); END IF;
IF TG_OP IN ('INSERT','UPDATE') THEN new_json := to_jsonb(NEW); END IF;

FOR k IN SELECT jsonb_object_keys(COALESCE(new_json, old_json)) LOOP
    IF k LIKE '%\_id' AND k NOT IN ('parent_id','teyinat_id','istirakci_id') THEN
        BEGIN
            rec_id := (COALESCE(new_json, old_json) ->> k)::INTEGER;
            EXIT;
        EXCEPTION WHEN OTHERS THEN CONTINUE;
        END;
    END IF;
END LOOP;

INSERT INTO audit.audit_log (sxem, cedvel, qeyd_id, emeliyyat, kohne_deyer, yeni_deyer)
VALUES (TG_TABLE_SCHEMA, TG_TABLE_NAME, rec_id, TG_OP, old_json, new_json);
RETURN COALESCE(NEW, OLD);

Seed-də iştirakçı qalib=TRUE yazılanda tender avtomatik yenilənir (Dərs 1-dəki əl ilə UPDATE-ə ehtiyac qalmır):

CREATE TRIGGER trg_tender_qalib AFTER INSERT OR UPDATE OF qalib ON satinalma.tender_istirakci
    FOR EACH ROW EXECUTE FUNCTION satinalma.tender_qalib_trigger_func();

3.4. Mərhələ progressi → layihə progressi

Mərhələlər dəyişən kimi əsas layihənin progres sütunu yenilənir — hesabatlar həmişə təzə olur:

CREATE TRIGGER trg_merhele_progres AFTER INSERT OR UPDATE OR DELETE ON layihe.layihe_merhele
    FOR EACH ROW EXECUTE FUNCTION layihe.merhele_progres_func();
Trigger necə işləyir? Trigger = cədvəl üzərindəki hadisəyə (INSERT/UPDATE/DELETE) reaksiya. BEFORE — dəyişiklikdən əvvəl, AFTER — sonra. FOR EACH ROW — dəyişən hər sətir üçün. EXECUTE FUNCTION — çağırılacaq funksiya.

Nümunə — layihe_budce_fakt (LEFT JOIN + COALESCE + GROUP BY + CASE):

CREATE OR REPLACE VIEW hesabat.layihe_budce_fakt AS
SELECT
    l.layihe_id, l.kod, l.ad AS layihe_adi, l.plan_budce,
    COALESCE(SUM(x.mebleg), 0) AS fakt_xerc,
    l.plan_budce - COALESCE(SUM(x.mebleg), 0) AS qaliq,
    CASE WHEN l.plan_budce > 0
         THEN ROUND(100.0 * COALESCE(SUM(x.mebleg), 0) / l.plan_budce, 2)
         ELSE 0 END AS faiz
FROM layihe.layihe l
LEFT JOIN maliyye.xerc x ON x.layihe_id = l.layihe_id
WHERE l.silinib = FALSE
GROUP BY l.layihe_id
ORDER BY l.layihe_id;

4.3. Nümunə view — layihe_tam_icmal

Birdən çox cədvəli JOIN edib, subquery ilə saylar hesablayır:

CREATE OR REPLACE VIEW hesabat.layihe_tam_icmal AS
SELECT
    l.layihe_id, l.kod, l.ad AS layihe_adi,
    mue.ad AS muessise, st.ad AS status, seh.ad AS seher,
    l.plan_budce,
    COALESCE(x.fakt_xerc, 0) AS fakt_xerc,
    l.plan_budce - COALESCE(x.fakt_xerc, 0) AS qaliq,
    l.progres,
    (SELECT COUNT(*) FROM risk.risk r WHERE r.layihe_id = l.layihe_id) AS risk_sayi,
    (SELECT COUNT(*) FROM keyfiyyet.qusur q
     JOIN keyfiyyet.yoxlama y ON y.yoxlama_id = q.yoxlama_id
     WHERE y.layihe_id = l.layihe_id AND q.status != 'baglanib') AS aciq_qusur,
    (SELECT COUNT(DISTINCT t.isci_id) FROM kadr.layihe_isci_teyinat t
     WHERE t.layihe_id = l.layihe_id) AS isci_sayi,
    l.bashlama_tarixi, l.son_tarix
FROM layihe.layihe l
JOIN ref.muessise mue ON mue.muessise_id = l.muessise_id
JOIN layihe.layihe_status st ON st.status_id = l.status_id
LEFT JOIN ref.seher seh ON seh.seher_id = l.seher_id
LEFT JOIN (SELECT layihe_id, SUM(mebleg) AS fakt_xerc FROM maliyye.xerc GROUP BY layihe_id) x
       ON x.layihe_id = l.layihe_id
WHERE l.silinib = FALSE;

4.4. Nümunə view — anbar_qaliqlari

CROSS JOIN bütün anbar × material kombinasiyalarını yaradır; CASE ilə daxil/çıxar hesablanır; HAVING sıfır balansı gizlədir:

CREATE OR REPLACE VIEW hesabat.anbar_qaliqlari AS
SELECT
    a.ad AS anbar, mn.ad AS material, mn.vahid,
    COALESCE(SUM(CASE WHEN mh.hereket_novu = 'daxil' THEN mh.miqdar
                      WHEN mh.hereket_novu = 'cixar' THEN -mh.miqdar
                      ELSE 0 END), 0) AS qaliq
FROM logistika.anbar a
CROSS JOIN ref.material_novu mn
LEFT JOIN logistika.material_hereket mh
       ON mh.anbar_id = a.anbar_id AND mh.material_novu_id = mn.material_novu_id
GROUP BY a.anbar_id, a.ad, mn.material_novu_id, mn.ad, mn.vahid
HAVING COALESCE(SUM(CASE WHEN mh.hereket_novu = 'daxil' THEN mh.miqdar
                         WHEN mh.hereket_novu = 'cixar' THEN -mh.miqdar ELSE 0 END), 0) != 0
ORDER BY a.ad, mn.ad;
