Dərs 1–7-də sistemi mock AI rejimində qurduq və sınaqdan keçirdik. İndi sistemi real AI ilə tam idarəetməyə keçiririk: real API açarları, AI_MODE=live, təcili dayandırma (kill-switch), monitoring və ən əsası — məlumat anonimləşdirməsi (AI-ya real şəxsi məlumat göndərmədən təhlil etmək).

KRİTİK XƏBƏRDARLIQ: Bu ERP real şəxsi məlumatlar (işçilərin FIN-i, ad-soyadı, VÖEN, telefon) saxlayır. Bu məlumatları xarici AI API-lərinə (DeepSeek/Anthropic) birbaşa göndərmək qanuni və təhlükəsizlik riskidir! Bu dərsin 5-ci hissəsi bu problemi həll edir.
Real fayllar: backend/.env, backend/.env.example (AI_MODE, DEEPSEEK_*, ANTHROPIC_*)

2.1. Canlı keçid qaydaları

  • Əvvəlcə bir agent ilə sınaq edin (məsələn yalnız Xərc Analitiki);
  • Xərc limiti qoyun — ai_log cədvəlindəki serf_olunan_xerc-i izləyin;
  • Təsdiq rejimi — AI qərarları tesdiq_status='golecek' qalsın, avtomatik icra olunmasın;
  • Nəticə keyfiyyəti qənaətbəxş olana qədər temperature-u aşağı saxlayın (0.1–0.3).

2.2. Human-in-the-loop — insan təsdiqi axını

Tam avtomatlaşdırmadan əvvəl hər AI qərarı insan tərəfindən təsdiqlənməlidir. Bu axın bazanın mövcud strukturu ilə dəstəklənir:

-- 1. AI qərarı 'teklif' statusu ilə yaranır (ai_qerar)
INSERT INTO ai.ai_qerar (teyinat_id, qerar_novu, mezmun, esaslandirma, eminlik, status)
VALUES (10, 'budce_tovsiyesi',
        '{"aksiya": "Material alışını rübün sonuna saxla"}'::jsonb,
        'Cari xərc-progres nisbəti büdcənin aşağı tamamlanacağını göstərir.',
        92.50, 'teklif');

-- 2. İnsan təsdiqləyir → status 'tesdiqlendi', tesdiq_eden yazılır
UPDATE ai.ai_qerar
SET status = 'tesdiqlendi',
    tesdiq_eden = 1,
    tesdiq_tarixi = NOW()
WHERE qerar_id = 1;

-- 3. Təsdiqlənmiş qərarların siyahısı
SELECT q.qerar_novu, q.eminlik, q.status, t.teyinat_novu, a.ad AS agent
FROM ai.ai_qerar q
JOIN ai.ai_teyinat t ON t.teyinat_id = q.teyinat_id
JOIN ai.ai_agent a ON a.agent_id = t.agent_id
WHERE q.status = 'teklif'
ORDER BY q.eminlik DESC;

Bu yanaşma "insan nəzarətində AI" prinsipini təmin edir: AI təklif edir, insan qərar verir. Yalnız statistik məlumat verən agentlər (məsələn xərc proqnozu) avtomatlaşdırıla bilər.

3 Kill-Switch — Təcili Dayandırma

Kill-switch — AI əməliyyatlarını dərhal dayandırma mexanizmi. Problem yaranarsa (yanlış qərar, xərc partlaması, API xətası) bütün AI çağırışlarını bloklayır.

3.1. Sadə kill-switch — .env bayrağı

# backend/.env-yə əlavə et
AI_KILL_SWITCH=false

aiService-də yoxlayın:

// aiService.js
const KILL_SWITCH = process.env.AI_KILL_SWITCH === 'true';

async function execute({ provider, tapşırıqNovu, prompt, sistem }) {
  if (KILL_SWITCH) {
    throw new Error('Kill-switch aktivdir — AI əməliyyatları dayandırılıb');
  }
  if (AI_MODE === 'mock') return callMock(prompt, tapşırıqNovu);
  ...
}

İstifadə: Problem olan kimi AI_KILL_SWITCH=true edib serveri restart edin → bütün AI sorğuları dayanır, sistem mock olmasa da funksional qalır (baza və əsas API işləyir).

3.2. Avtomatik kill — xərc limiti

Günlük xərc limitini keçən kimi avtomatik dayanma. Bunu bir sorğu ilə izləmək olar:

// Günlük AI xərci (ai_log-dan)
SELECT DATE(created_at) AS gun, COALESCE(SUM(serf_olunan_xerc),0) AS xerc_azn
FROM ai.ai_log
WHERE created_at >= CURRENT_DATE
GROUP BY 1;

Bu dəyər limitdən yuxarı olarsa, execute() əvvəlcədən sorğunu rədd edə bilər.

4 Monitoring — AI Fəaliyyətinin İzlənməsi

Live rejimdə hər AI əməliyyatı izlənilməlidir. Dərs 1-də qurduğumuz ai sxemi bunu dəstəkləyir.

4.1. Əsas monitoring sorğuları

-- 1. Agentlər üzrə tapşırıq yükü və effektivlik (04_analitik_sorgular.sql AI-1)
SELECT ag.ad AS agent, ag.vezife,
       COUNT(t.teyinat_id) AS tapşiriq,
       COUNT(t.teyinat_id) FILTER (WHERE t.status = 'hazir') AS hazir,
       COUNT(t.teyinat_id) FILTER (WHERE t.status = 'xesver') AS xesver,
       ROUND(AVG(t.netice_qiymeti), 1) AS orta_qiymet
FROM ai.ai_agent ag
LEFT JOIN ai.ai_teyinat t ON t.agent_id = ag.agent_id
GROUP BY ag.agent_id ORDER BY tapşiriq DESC;

-- 2. AI xərc izləmə (AI-2)
SELECT ag.ad AS agent,
       COUNT(l.log_id) AS log_sayi,
       COALESCE(SUM(l.serf_olunan_tokens), 0) AS tokens,
       COALESCE(SUM(l.serf_olunan_xerc), 0) AS xerc_azn
FROM ai.ai_agent ag
LEFT JOIN ai.ai_log l ON l.agent_id = ag.agent_id
GROUP BY ag.agent_id ORDER BY xerc_azn DESC;

-- 3. Proqnoz dəqiqliyi (AI-3)
SELECT l.kod, l.ad AS layihe, p.prognoz_novu,
       p.prognoz_deyer, p.real_deyer,
       ROUND(100.0 * (1 - ABS(p.prognoz_deyer - COALESCE(p.real_deyer, p.prognoz_deyer))
             / NULLIF(p.prognoz_deyer, 0)), 2) AS doqruluk
FROM ai.ai_prognoz p
JOIN layihe.layihe l ON l.layihe_id = p.layihe_id
ORDER BY p.prognoz_id;

4.4. Monitoring HTTP endpointi

Əməliyyat komandası üçün AI vəziyyətini göstərən sadə endpoint yarada bilərsiniz. src/routes/ai.routes.js-a əlavə edin:

// GET /api/ai/status — AI sisteminin canlı vəziyyəti
async function status(req, res, next) {
  try {
    const { pool } = require('../config/db');

    // Son 24 saatın statistikası
    const { rows } = await pool.query(`
      SELECT COUNT(*) FILTER (WHERE status = 'hazir') AS hazir,
             COUNT(*) FILTER (WHERE status = 'xesver') AS xesver,
             COUNT(*) FILTER (WHERE status = 'islemede') AS islemede,
             COALESCE(SUM(serf_olunan_xerc), 0) AS xerc_azn
      FROM ai.ai_teyinat t
      LEFT JOIN ai.ai_log l ON l.teyinat_id = t.teyinat_id
      WHERE t.created_at >= NOW() - INTERVAL '24 hours'`);

    res.json({
      rejim: process.env.AI_MODE,
      kill_switch: process.env.AI_KILL_SWITCH === 'true',
      son_24saat: rows[0],
      vaxt: new Date().toISOString(),
    });
  } catch (e) { next(e); }
}

router.get('/status', status);

4.5. AI xərc və qiymət cədvəli

Hər modelin qiyməti ai.ai_model cədvəlində saxlanılır (seed-dən). Live rejimdə xərci proqnozlaşdırmaq üçün:

SELECT ad, provider, model_ref, rolu,
       qiymet_1000_input, qiymet_1000_output,
       max_tokens, temperature
FROM ai.ai_model
WHERE aktif = TRUE
ORDER BY qiymet_1000_output DESC;

Gözlənilən nəticə: Claude Opus ən bahalı (15.0/75.0 $), DeepSeek Chat ən iqtisadi (0.14/0.28 $). Təxmini sorğu xərci = (input_token/1000 × input_qiymet) + (output_token/1000 × output_qiymet).

5 Məlumat Anonimləşdirməsi (ƏN VACİB HİSSƏ)

ERP-də şəxsi məlumatlar var: işçi ad-soyadı, FIN, telefon, VÖEN. Bunları xarici AI-ya göndərmək əvəzinə anonimləşdiririk.

5.1. Anonimləşdirmə funksiyası

src/utils/anonim.js — şəxsi sahələri maskalayır:

// Şəxsi məlumatları maskalayan köməkçi
function anonimlesdir(qeyd) {
  if (!qeyd) return qeyd;
  const c = { ...qeyd };

  // Ad-soyad → 'Elçin M.' formatı
  if (c.ad_soyad) c.ad_soyad = c.ad_soyad.replace(/(\S+)\s+.*/, '$1 ' +
    c.ad_soyad.split(/\s+/).slice(1).map(s => s[0] + '.').join(' '));

  // FIN → 'FIN**1'
  if (c.fin) c.fin = c.fin.slice(0, 3) + '**' + c.fin.slice(-1);

  // VÖEN → son 4 rəqəm
  if (c.voen) c.voen = 'VOEN-' + c.voen.slice(-4);

  // Telefon → +994 *** ** ** 01
  if (c.telefon) c.telefon = c.telefon.replace(/\d{2}$/, '**');

  // Email → ilk hərf + ***@domain
  if (c.email && c.email.includes('@')) {
    const [ad, dom] = c.email.split('@');
    c.email = ad[0] + '***@' + dom;
  }

  return c;
}

// Sətir massivini anonimləşdir
function massiviAnonimlesdir(rows, sahəler) {
  return rows.map(r => {
    const c = { ...r };
    for (const sahə of sahəler) {
      if (c[sahə] !== undefined) c[sahə] = anonimlesdir({ [sahə]: c[sahə] })[sahə];
    }
    return c;
  });
}

module.exports = { anonimlesdir, massiviAnonimlesdir };

5.2. Nəticə nümunəsi

Q14 sorğusunun nəticəsi AI-ya bu formada verilir:

// Əsl məlumat:
ad_soyad: "Elçin Məmmədov", fin: "FIN001", maas: 4800

// AI-ya gedən anonim versiya:
ad_soyad: "Elçin M.", fin: "FIN**1", maas: 4800

Maaş kimi statistik məlumatlar qalır (təhlil üçün lazımdır), amma şəxsiyyəti müəyyən edən sahələr maskalanır.

5.3. Anonimləşdirməyi axına necə bağlamaq

promptBuilder-da sorğu nəticəsini AI-ya verməzdən əvvəl maskalayın:

// promptBuilder.js — baza məlumatlarını yığarkən
const { massiviAnonimlesdir } = require('../utils/anonim');

// AI-ya gedən cədvəl məlumatlarını maskala
const təhlükəsiz = massiviAnonimlesdir(
  verilənlər.sətirlər || [],
  ['ad_soyad', 'fin', 'voen', 'telefon', 'email']
);
Unutmayın: ai.ai_teyinat.giris_json və cixis_json bazada saxlanılır. Anonimləşdirmə həm xaricə gedən, həm də bazada saxlanılan məlumatlara tətbiq olunmalıdır — beləliklə, hətta baza sızsa belə, real şəxsi məlumatlar açıqlanmır.

7 Deploy Mexanikası

7.1. Proses meneceri — PM2 (serverdə)

npm install -g pm2
cd backend
pm2 start src/server.js --name deepseek-erp
pm2 save
pm2 startup

7.1.1. Mühit ayrılması (dev/staging/prod)

Hər mühit üçün ayrıca .env faylı saxlamaq düzgün təcrübədir. Heç vaxt mühit dəyişənlərini hardcode etməyin:

# Qovluq strukturu
backend/
├── .env            # inkişaf (dev) — AI_MODE=mock
├── .env.staging    # test mühiti — AI_MODE=mock, ayrıca DB
├── .env.production # canlı — AI_MODE=live, real açarlar, ayrıca DB
# Deploy zamanı düzgün mühiti yüklə
NODE_ENV=production pm2 start src/server.js --name deepseek-erp --env production
# server.js-də: dotenv.config({ path: `.env.${process.env.NODE_ENV}` })

Canlı bazada deepseek_erp_v6_prod kimi ayrıca baza istifadə edin — test məlumatları canlı bazaya qarışmamalıdır.

7.2. Yoxlama siyahısı (deploy əvvəli)

  1. AI_MODE=mock ilə bütün Dərs 7 testləri keçir (safe deploy);
  2. Real açarlar env-də, gitignore-da;
  3. Anonimləşdirmə aktiv;
  4. Kill-switch false vəziyyətində, əməliyyat proseduru hazır;
  5. PostgreSQL ehtiyat nüsxəsi qurulub:
# Gündəlik ehtiyat nüsxə (cron üçün)
pg_dump -U deepseek_admin -h localhost deepseek_erp_v6 \
  -F c -f backups/deepseek_$(date +%Y%m%d).dump

# Bərpa
pg_restore -U deepseek_admin -h localhost -d deepseek_erp_v6 \
  -c backups/deepseek_20260825.dump

7.4. Geri qayıtma (rollback) proseduru

Live rejimdə problem yaranarsa, sürətli geri qayıtma planı hazır olmalıdır:

  1. 1-ci addım (dərhal): AI_KILL_SWITCH=true → serveri restart edin. Bütün AI sorğuları dayanır; əsas API və baza işləməyə davam edir.
  2. 2-ci addım (5 dəq): AI_MODE=mock → sorğular nümunə cavabla işləyir.
  3. 3-cü addım (30 dəq): Son etibarlı build-i deploy edin (git checkout → pm2 reload).
  4. 4-cü addım (verifikasiya): Dərs 7-dəki yoxlama siyahısını qaçırın: health, auth, AI status.
# Kill-switch aktivləşdir və restart
echo "AI_KILL_SWITCH=true" >> backend/.env
pm2 reload deepseek-erp

# Mock-a qayıt
sed -i '' 's/AI_MODE=live/AI_MODE=mock/' backend/.env
pm2 reload deepseek-erp

# AI statusu yoxla
curl http://localhost:5001/api/ai/status -H "Authorization: Bearer $TOKEN"
# → {"rejim": "mock", "kill_switch": true, ...}

8 Təkrarlama Tapşırığı

Yekun tapşırıq: Dərsə baxmadan:
  1. AI_MODE=live keçidinin 3 riskini sadalayın və hər biri üçün tədbir yazın.
  2. Kill-switch-i necə quraşdırarsınız? Nə vaxt işə düşməlidir?
  3. Anonimləşdirmə funksiyası yazın: ad_soyad və fin maskalayan.
  4. Günlük AI xərci limitini yoxlayan sorğu yazın.
  5. Deploy siyahısını 5 addımda yazın.
  6. Fikirləşin: AI-ya büdcə proqnozu üçün hansı minimal məlumat dəsti kifayətdir? (Anonimləşdirmədən sonra nə qalır?)
Bu addımda nə öyrəndin? Real API açarlarının idarəsi; mock → live keçid strategiyası; kill-switch və avtomatik xərc limiti; monitoring sorğuları (ai_log, ai_mesaj, audit); məlumat anonimləşdirməsinin vacibliyi və tətbiqi; prompt injection qoruması; PM2 və pg_dump ilə deploy.
